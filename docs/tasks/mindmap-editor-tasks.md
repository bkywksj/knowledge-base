# 可编辑思维导图（自研）

> 来源：2026-11-14 用户反馈「想直接编辑思维导图、不习惯 Markdown」。
> 决策：不引入第三方导图库、不复制他人源码，按通用原理自研（React + TS，纯函数可单测）。

## 核心约定

- **数据仍是笔记正文的 Markdown**：标题 + 嵌套列表 = 导图节点；中心主题 = 笔记标题。
  不加笔记类型、不改数据库、不改同步；搜索 / AI / 导出 / 手机端（显示为多级列表）全部免改。
- **只有「纯大纲」笔记可编辑**：正文里出现段落、表格、代码块等 → 导图保持只读并说明原因，
  否则写回会丢内容。
- 写回格式对齐编辑器的 tiptap-markdown 序列化（`-` 无序、紧凑列表、嵌套缩进 = 父标记宽度 + 1）。

      原位输入框改文字、撤销重做（树快照）
- [x] T4 接入 `MindMapView`：可编辑时工具栏出现「编辑」开关；写回编辑器走自动保存
- [x] T5 「新建思维导图」入口（新建笔记下拉）：新建后打开导图分栏并直接进编辑模式
      （分栏而非全屏：左边编辑器同步显示对应的列表，方便对照；需要时可点全屏）
- [x] T6 实测（2026-11-14）：
      - 浏览器单独挂载：布局 / 键盘增删改移 / Esc 撤新建 / 撤销重做 / 改中心主题 / 写回 Markdown 全部正确
      - 调试版独立实例（dev 库，测完用快照还原）：「新建思维导图」→ 直接进导图编辑 → 写回编辑器 → Ctrl+S 入库正确；
        编辑器自己序列化的列表与导图输出逐字一致；切走再切回不会误标「未保存」
      - 实测修掉两处：默认视图为「阅读」时新建导图进不了编辑（现强制切编辑模式；阅读 / 源码模式下编辑按钮置灰说明原因）；
        编辑器在文末补的空段落 `<p></p>` 被误判为正文，改过一个字导图就只读（现按空行处理）
      - 曾怀疑「焦点不在正文时 Ctrl+S 保存两次」，复查证实是验收工具把同一条提示报了两遍：
        页面只收到 1 次 keydown、DOM 里只有 1 条「保存成功」，应用本身没有这个问题

### 快捷键（编辑模式）

| 键 | 作用 |
|---|---|
| Tab | 加子节点 |
| Enter | 加同级节点（中心主题上 = 加子节点） |
| Delete / Backspace | 删除节点（含子树） |
| F2 / 双击 | 改文字（Enter 确认、Esc 取消） |
| 方向键 | 在节点间移动选中 |
| Alt + ↑ / ↓ | 同级内上移 / 下移 |
| Alt + → / ← | 降级（变成上一个同级的子节点）/ 升级 |
| Space | 折叠 / 展开 |
| Ctrl+Z / Ctrl+Y | 撤销 / 重做 |
