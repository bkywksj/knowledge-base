## 🔴 执行规则（每项开工前必读）

1. **先给计划、等确认再动手**：涉及哪些文件、改什么、桌面端会不会受影响、怎么验证。
2. **不删功能**：每页动手前，先把该页现有功能逐条列出（见「M0-2 功能底稿」），改完逐条勾回。
3. **改完必须验证**：`npx tsc --noEmit` + `pnpm test` 必过；界面在智码浏览器手机画幅里截图对照原型（见下方「验证方法」）；
   键盘 / 手势 / 安全区 / 三键导航相关的，必须上真机。
4. **桌面端零回归**：只改 `Mobile*` 页面和移动端专用组件；动到共用组件（TiptapEditor、turnModel 等）时，桌面端也要回归一遍。
5. **一页一提交**，scope 写 `mobile`，例：`feat(mobile): 首页按 v4 原型重做`。

## 设计规则（从原型定稿而来，落地时照抄数值）

| 项 | 规则 |
|---|---|
| 颜色来源 | **一律用 PC 主题变量 `--kb-*`**（9 套主题手机端自动可用），手机端禁止再写死 `#1677FF` / `bg-slate-*` |
| 文字对比度 | 正文 ≥ 4.5:1。PC 原值次要文字 3.0:1 不达标 → 手机端令牌层覆盖文字色（原型：次要 `#6E6888`、主色字 `#6A50CE`） |
| 圆角 | 6 / 8 / 10 / 12 四档；底部面板顶部 16；内层比外层小一档 |
| 字号 / 字重 | 大标题 28 · 区块标题 17 · 列表标题 16 · 正文 15 · 辅助 13 · 最小 12；标题一律 700，不用 500 |
| 阴影 | 按钮、图标、控件**无阴影**；只有浮起卡片（继续编辑 / 日记当天 / AI 回复）带柔和阴影 |
| 容器 | 一个容器只用一种手段：分组面板只靠白底，浮起卡只靠阴影；操作格放进一块面板里分格，不一格一卡 |
| 图标 | 列表 / 菜单 / 工具栏用线性中性色；只有金刚区用彩色实心图标（无底色块、无阴影） |
| 主色面积 | ≤ 10%：只给主按钮、选中态、双链记号 |
| 功能记号 | 双链「↔ 链入 N」：笔记行、编辑器、待办关联、搜索结果、AI 引用 |
| 触控 | 热区 ≥ 44×44（小控件用透明热区撑开） |
| 底栏 | 实色 + 细线，不用毛玻璃；遮罩从状态栏下方开始 |

## 验证方法

| 场景 | 做法 |
|---|---|
| 样式 / 布局 | 起 vite（`pnpm dev`，端口见 `tauri.conf.json` 的 devUrl）→ 智码 `browser_open(devUrl, device="mobile")`，`useIsMobile` 按 UA 判成手机布局 |
| 数据 | 浏览器里没有 Tauri，invoke 会失败：在页面里 `import('/src/lib/api')` 替换对应 api 喂假数据（见记忆 feedback_ui_test_data_safety） |
| 键盘 / 手势 / 安全区 / 原生层 | 真机：`env CARGO_TARGET_DIR="C:\cargo-target\kb-android" pnpm tauri android dev`（中文路径 NDK 坑，见 bug-detective 技能） |
| 回归门槛 | `npx tsc --noEmit`、`pnpm test`；动到 Rust 时 `cargo check` 桌面 + Android target |
